# AQL Level I · 6.5 Design

## Intent

เปลี่ยนระบบตรวจรับบรรจุภัณฑ์จาก AQL ระดับ II · 6.5 เป็นระดับ I · 6.5 ตามตารางอ้างอิงที่ผู้ใช้ส่งให้ เพื่อให้ค่า Code, Sample Size, AC และ RE ที่คำนวณหลังกรอกจำนวน Lot ตรงกับตารางใหม่ทั้งหน้าเว็บและ Apps Script

## Goals

- ใช้แหล่งข้อมูล AQL ชุดเดียวใน `apps-script/Code.gs` สำหรับการคำนวณและ `bootstrap`.
- แสดงหัวข้อและตารางอ้างอิงเป็น `AQL ระดับ I · 6.5`.
- ใช้ค่าตามภาพใหม่ครบทุกช่วง:

| Lot / Batch | Code | Sample | AC | RE |
| --- | --- | ---: | ---: | ---: |
| 2–8 | A | 2 | 0 | 1 |
| 9–15 | A | 2 | 0 | 1 |
| 16–25 | B | 3 | 0 | 1 |
| 26–50 | C | 5 | 0 | 1 |
| 51–90 | C | 5 | 0 | 1 |
| 91–150 | D | 8 | 1 | 2 |
| 151–280 | E | 13 | 1 | 2 |
| 281–500 | F | 20 | 2 | 3 |
| 501–1,200 | G | 32 | 5 | 6 |
| 1,201–3,200 | H | 50 | 7 | 8 |
| 3,201–10,000 | J | 80 | 10 | 11 |
| 10,001 ขึ้นไป | J | 80 | 10 | 11 |

## Non-goals and constraints

- ไม่เปลี่ยนวิธีให้ผู้ตรวจเลือกผลรวม Pass / Fail เอง และไม่ auto-select ผลรวมจาก AQL.
- ไม่แก้ไขข้อมูลตรวจรับเก่าที่บันทึกแล้วหรือทำ spreadsheet backfill; การส่งใหม่และการแก้ไขใบตรวจรับจะคำนวณจากตารางระดับ I.
- คงกรณี Lot = 1 เป็นการตรวจทั้ง Lot: Code A, Sample 1, AC 0, RE 1.
- คงพฤติกรรม Lot ที่มากกว่า 10,000 ให้ใช้แถวสุดท้าย J / 80 / 10 / 11.

## Approaches

1. **แหล่งข้อมูลกลางใน Apps Script (เลือกใช้):** เปลี่ยน `AQL_TABLE` และ `AQL_LEVEL` ใน backend แล้วให้ frontend ใช้ค่าจาก `bootstrap`; แก้ข้อความที่ hardcode และเพิ่ม regression tests. ทำให้การคำนวณหลังบ้านและตารางที่ผู้ใช้เห็นตรงกัน.
2. **แก้เฉพาะ frontend:** เปลี่ยนข้อความ/ตารางที่หน้าเว็บ แต่ปล่อย backend เดิมไว้. ไม่เลือก เพราะข้อมูลที่บันทึกจะยังใช้ระดับ II.

## Verification

- เพิ่ม/แก้ tests ให้ตรวจ metadata ว่าเป็นระดับ I และตรวจจุดเปลี่ยนทุกช่วงของตาราง รวมถึง Lot = 1, 10,000, 10,001 และค่าที่ไม่ถูกต้อง.
- รัน contract test, Apps Script mock suite, JavaScript syntax check และ `git diff --check` ก่อน commit.
- หลังผู้ใช้อนุมัติการเผยแพร่ ค่อย push GitHub Pages และ deploy Apps Script เวอร์ชันใหม่ตาม workflow เดิม.
